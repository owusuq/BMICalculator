# Overview

As a software engineer, I wanted to learn how a web application can store its data in the cloud instead of throwing it away after every request. I extended my Module 1 Django BMI Calculator so that every calculation is saved to a **Google Firebase Firestore** cloud database, and the app can read, edit and delete those saved records.

The user enters height (cm) and weight (kg), the app calculates the BMI and category, saves the result to Firestore, and a History page shows every saved calculation with options to add a note or delete it.

My purpose in writing this software was to learn how a NoSQL cloud database works (collections and documents), how to connect to it securely from Python with a service account, and how to perform all four CRUD operations from a web app.

**Cloud database:** Firebase Firestore, collection `bmi_records`. Each document has `height_cm`, `weight_kg`, `bmi`, `category`, `note` and `created_at`.

| Operation | Where it happens |
|-----------|------------------|
| Create | `result` view saves each calculation |
| Read | `history` view lists saved records |
| Update | `update_record` view edits a note |
| Delete | `delete_record` view removes a record |

# Cloud Database

I used **Firebase Firestore** (Google Cloud), a NoSQL document database. Instead of tables and rows it stores documents (like Python dictionaries) in collections. All database code is in `bmi_project/bmi_calculator/firestore_service.py` and connects to Firestore's REST API over HTTPS using the `requests` library and the project's Firebase web API key.

The structure is a single collection:

```
bmi_records/
    <auto-generated document id>/
        height_cm, weight_kg, bmi, category, note, created_at
```

# How to Run

1. Clone the repository and open a terminal in the project folder.
2. Create and activate a virtual environment, then install the requirements:
   `pip install -r requirements.txt`
3. In the [Firebase Console](https://console.firebase.google.com/) open your project, go to **Build > Firestore Database > Rules**, and allow access to the `bmi_records` collection (for this class project):
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /bmi_records/{doc} {
         allow read, write: if true;
       }
     }
   }
   ```
   Click **Publish**. (These open rules are only suitable for a demo project; a real app would add user login and stricter rules.)
4. If you use your own Firebase project, set the environment variables `FIREBASE_PROJECT_ID` and `FIREBASE_API_KEY` (or edit them at the top of `firestore_service.py`).
5. From the `bmi_project` folder run: `python manage.py runserver`
6. Open `http://127.0.0.1:8000/`

If the database cannot be reached the calculator still works, and the History page shows the reason.

# Web Pages

* **Home (`/`)** - height and weight form.
* **Result (`/result/`)** - shows BMI and category and saves the record to Firestore.
* **Tips (`/tips/`)** - health tips for the BMI category.
* **History (`/history/`)** - reads saved records from Firestore; edit a note or delete a record.
